# 网络体检

手表说「检测更新失败 / 下载失败」的时候,先跑一下它,看看问题出在哪一段。

## 它做什么

手动运行,依次访问三个测试地址,报告每个地址**通不通、花了多久、拿到多少字节**:

| 测试项 | 测的是什么 |
|---|---|
| GitHub 加速通道 | 应用内更新和插件商店默认走的那条路 |
| jsDelivr CDN | 另一条常用的分发通道 |
| 普通网页(百度) | 基础的 DNS / 联网能力 |

最后给一个结论:

- **全部通** → 网络没问题,之前的失败多半是服务器临时不稳定;
- **全部不通** → 先检查 WiFi 或流量到底连上没有;
- **部分不通** → 通常是某条加速通道的问题,换个时间再试。

## 用了哪些权限

| 权限 | 为什么需要 |
|---|---|
| `network` | 访问测试地址(`sos-http`) |

这是**中风险**权限,安装时不会自动勾选,需要你在授权页手动勾上。
没勾的话插件会直接告诉你「没有 network 权限」并停下,不会静默失败。

## 数据存在哪

测试时的临时文件写在 `$SOS_DATA/probe.bin`,每次覆盖,跑完就删。
除此之外不留任何东西。

## 触发时机

- `manual` —— 只在你在应用里点「运行」时执行(不会自己在后台联网,你可以放心)

## 代码看点

- **先在开头检查权限**:`sos-*` 命令在权限不足时会以退出码 3 失败,
  与其等三个测试项各报一次错,不如开头一次性说清楚;
- **用秒级时间戳测时延**:`date '+%s'` 前后取两次相减,
  精度虽然只有秒,但判断「通不通、快不快」足够了,而且不依赖任何额外工具;
- **不带用户数据联网**:这里只访问公开的索引文件,不发送任何东西 ——
  隐私上最省心,审核时也不会有「上传数据」的疑点。
