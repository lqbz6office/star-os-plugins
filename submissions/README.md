# 投稿区

想让你的插件出现在 Star OS 的插件商店里,把插件放这里提 PR,或者开一个「插件投稿」issue。

## 提 PR 的步骤

1. Fork 本仓库;
2. 把你的插件目录放到 `submissions/<你的插件id>/`,内容和 `plugins/` 下的插件一样:
   ```
   submissions/com.you.myplugin/
   ├── plugin.json
   ├── main.sh
   └── README.md
   ```
3. 提 PR。作者会用「Star OS 插件工具」跑一遍审核(规则见
   [`docs/插件开发文档.md`](../docs/插件开发文档.md#8-审核红线));
4. 通过后由维护者执行「上架」—— 工具会把插件搬到 `plugins/<id>/`、
   打包到 `dist/`、更新 `index.json`,一起合进 main;
5. 上线后所有用户在新版应用的商店里就能看到。

> 你不需要自己打包 `.sosp`、也不用手改 `index.json` —— 那些由工具做,
> 避免手算出错(尤其是 sha256)。

## 提 issue 的步骤

如果你不熟悉 Git:开一个「插件投稿」issue,贴上插件包下载链接和说明。
维护者审核通过后会代为合入。

## 审核会看什么

- **能不能跑**:清单字段、入口脚本、目录结构对不对;
- **权限合不合理**:是不是按最小够用原则申请的(多申请一样东西就会被问);
- **有没有危险动作**:删系统目录、刷分区、提权、改 SELinux 之类一律拒;
- **有没有绕包装命令**:该走 `sos-*` 的却直接调 `getprop`/`settings`/`curl` 会被拒;
- **有没有二进制**:有就直接拒,没得商量。

## 被拒了怎么办

工具的报错会精确到**文件名 + 行号 + 原因**,照着改再重提就行。
改完记得把 `plugin.json` 里的 `versionCode` 加一。

## 上架之后要更新

同 id 重新提 PR 即可,工具会覆盖 `plugins/<id>/` 和 `dist/` 里的旧版本。
**`versionCode` 必须比上一版大**,否则用户端判断不出「有新版」。
`index.json` 里的 `downloads` 计数会被保留。
